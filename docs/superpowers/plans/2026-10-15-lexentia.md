# Lexentia Website Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Deliver the approved Lexentia website with a cinematic hero, expanding carousel, real Insights and official EU court records.

**Architecture:** Buildless HTML, CSS and browser JavaScript, with structured JSON content and dependency-free Node preparation/check scripts. Publish the assembled `dist/` privately through Sites. The lead owns hosting, integration, review and browser validation; one Luna worker owns site implementation and corrections.

**Tech Stack:** Semantic HTML, CSS, JavaScript ES modules, Node built-ins; no application dependency required.

**Spec:** `docs/superpowers/specs/2026-10-15-lexentia-design.md`

**Execution update:** The user's in-progress visual corrections at the top of the spec supersede the initial typography/carousel decisions. Retain the verified data pipeline; rebuild the scroll-driven hero and minimal layout, then incorporate auto-advance, readable slide text, section reveals and the left-logo/centred-menu header. Continue with the same implementation worker and lead validation.

## Global Constraints

- Preserve the firm's focus on EU and international civil service law and Belgian/international business and private law.
- Adapt Moonlit's full-width video hero and Legora's expanding image carousel to Lexentia.
- Retain French and English navigation/content support.
- No invented credentials, testimonials, client lists or results.
- No database, accounts or paid service is necessary for the requested public experience.
- Each case should link to the official EUR-Lex judgment and optionally the EU JUST record.
- Use a checked-in source snapshot with a repeatable refresh command and visible last-retrieved timestamp; no scheduled update is implied or configured.
- Lead agent reviews delegated code and the final diff before reporting completion.
- Keep work in this empty current checkout; do not change the eujust repository or production DNS.

## Review Focus

- A malformed or non-court feed record must be excluded without unsafe HTML or links.
- A failed source refresh must preserve the last valid snapshot and fail visibly.
- Empty searches and court/category combinations must display an understandable empty state.
- Reduced motion or blocked video must leave a usable poster, heading and actions.
- Mobile carousel and menu must work without page overflow or inaccessible hidden controls.

### Task 1: Content, provenance and free media

**Files:** `data/insights.json`, `data/cases.json`, `data/firm.json`, `public/assets/*`, `scripts/refresh-cases.mjs`, `scripts/lib/cases.mjs`, `tests/cases.test.mjs`, `ASSET_CREDITS.md`.

**Interfaces:** Case records `{celex, caseNumber, court, title, judgmentDate, officialUrl, recordUrl}` plus snapshot `{retrievedAt, sourceUrl, cases}`. Insights contain `{slug, title, date, author, category, summary, sourceUrl}`. `normalizeCases(records)` returns validated and deduplicated court records.

- [ ] Download suitable free media from the approved shortlist, using network escalation if required. Record exact author/source/license. Use actual Lexentia photographs for team identities.
- [ ] Run `node --test tests/*.test.mjs`; expect all content tests to pass. Record unavailable external sources honestly.
